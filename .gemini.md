## 📌 Cos'è TheView?
**TheView** è una dashboard web moderna per homelab e self-hosting, concepita come alternativa leggera, esteticamente appagante e dinamica a progetti come Homer, Heimdall o Dashy.
Il suo scopo è raccogliere i link ai vari servizi (Docker, web apps, ecc.) in un'unica pagina organizzata per categorie, supportando temi scuri/chiari, icone personalizzate, ricerca rapida e **Discovery automatica** (da Docker e Nginx Proxy Manager).

## 🛠️ Tech Stack
- **Framework:** SvelteKit (con Node Adapter)
- **Motore UI:** Svelte 5 (uso estensivo di Runes: `$state`, `$derived`, `$effect`, `onclick`)
- **Stile:** Tailwind CSS v4 (configurato direttamente via Vite e CSS layer)
- **Database:** SQLite tramite `better-sqlite3` e `drizzle-orm`
- **Autenticazione:** Sessioni JWT salvate in cookie (`admin_session`)
- **Deploy:** Dockerizzato, con build automatizzate via GitHub Actions

## 📂 Struttura del Progetto (Punti Chiave)
- `src/routes/+page.svelte`: La dashboard pubblica principale in cui gli utenti visualizzano i servizi e i widget.
- `src/routes/admin/+page.svelte`: Il pannello di amministrazione (protetto da password). Qui risiede la logica per la gestione categorie, servizi, impostazioni NPM e la **Discovery**.
- `src/routes/api/...`: Endpoint backend (gestione icone, auth, settings, status dei servizi e discovery).
- `src/lib/server/db/`: Contiene la configurazione di Drizzle ORM (`index.ts`) e lo schema del database (`schema.ts`).
- `src/lib/server/discovery.ts`: Core logic per interrogare il demone Docker (tramite socket `/var/run/docker.sock`) e le API di Nginx Proxy Manager per trovare e unire servizi non ancora aggiunti in dashboard.
- `data/`: Cartella persistita fuori dal container. Contiene il DB SQLite (`sqlite.db`), le icone caricate dagli utenti (`icons/`) e il file delle impostazioni (`settings.json`).

## ⚙️ Metodologia di Lavoro e Workflow
Quando scrivi codice per TheView, segui *strettamente* queste linee guida:

1. **Test in Locale:** Lo sviluppatore testa tipicamente il codice eseguendo il server dev locale (`npm run dev`) con Node.js, puntando a un ambiente di rete locale (es. router). I build completi (tramite GitHub Actions) richiedono minuti, quindi **evita di rompere il server di sviluppo** e controlla sempre i tuoi comandi.
2. **Deploy via GitHub Actions:** Il progetto utilizza un workflow (`.github/workflows/docker-publish.yml`) che esegue automaticamente la build e il push dell'immagine Docker (spesso multi-arch per amd64/arm64) quando avvengono push sul branch principale. Se modifichi dipendenze critiche (es. `Dockerfile`), assicurati che la pipeline non fallisca.
3. **Svelte 5 Runes:** Utilizza ESCLUSIVAMENTE la sintassi di Svelte 5.
   - Variabili reattive: `let count = $state(0);` (NIENTE `let count = 0;` o `$:`)
   - Eventi: `onclick={handler}` (NIENTE `on:click`)
   - Effetti: `$effect(() => { ... })`
4. **Protezione CSRF in Homelab:** Poiché la dashboard gira tipicamente dietro un reverse proxy (es. NPM) su IP locali o domini dinamici, il controllo CSRF stretto di SvelteKit blocca le richieste POST. Manteniamo sempre `csrf: { checkOrigin: false }` nel file `svelte.config.js`.
5. **UI & UX:** L'interfaccia deve risultare moderna e setosa.
   - Usa `transition:slide` o `transition:fade` (`import { slide } from 'svelte/transition'`) per i menu espandibili.
   - Non usare noiosi `alert()` o `prompt()` nativi se puoi evitarlo. Includi input in-line per le creazioni rapide (es. nuova categoria).
   - Privilegia bordi arrotondati (`rounded-xl` o `rounded-2xl`), sfumature, hover effects (`hover:scale-105`), e supporto robusto per la modalità scura (`dark:bg-gray-800`).
6. **Autenticazione:** L'accesso all'area Admin e alle chiamate API distruttive deve essere sempre protetto verificando `locals.isAdmin` nei `RequestHandler` (gestito tramite `hooks.server.ts`).

## 🧠 Storia Recente e Bug Risolti
- Abbiamo implementato un sistema di Discovery molto avanzato che fonde (`source: 'npm+docker'`) gli hostname intercettati da NPM con i container attivi di Docker.
- I form della discovery sono nascosti sotto un bottone `+` animato, in modo da non sporcare la UI e permettere all'utente di aggiungere descrizioni/icone *prima* di inviare la richiesta.

- Supporto ai temi avanzati (Dracula, Dracula Alucard, Catppuccin Latte/Macchiato) e layout a 3 righe per l'aggiunta/modifica dei servizi.
- Le icone estratte da SimpleIcons (caricate come SVG bianchi) vengono ora mostrate su uno sfondo colorato dinamicamente in base all'hex originale del brand (es. `background-color: #123456`).
- Sistema di autorisoluzione per `localhost` in Docker (`src/lib/server/dockerHost.ts`): le chiamate `fetch` interne a NPM o ai widget intercettano `localhost` o `127.0.0.1` e lo riscrivono nell'IP di rete Docker Host (es. 172.17.0.1) per aggirare il blocco loopback dei container senza network_mode host.
