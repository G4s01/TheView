## 📌 Cos'è TheView?
**TheView** è una dashboard web moderna per homelab e self-hosting, concepita come alternativa leggera, esteticamente appagante e dinamica a progetti come Homer, Heimdall o Dashy.
Il suo scopo è raccogliere i link ai vari servizi (Docker, web apps, ecc.) in un'unica pagina organizzata per categorie, supportando temi scuri/chiari (con varianti come Dracula e Catppuccin), icone personalizzate, ricerca rapida, controlli drag & drop e **Discovery automatica** (da Docker e Nginx Proxy Manager).

## 🛠️ Tech Stack
- **Framework:** SvelteKit (con Node Adapter)
- **Motore UI:** Svelte 5 (uso estensivo di Runes: `$state`, `$derived`, `$effect`, `onclick`)
- **Stile:** Tailwind CSS v4 (configurato direttamente via Vite e CSS layer) + Material Design vibes
- **Database:** SQLite tramite `better-sqlite3` e `drizzle-orm`
- **Autenticazione:** Sessioni JWT salvate in cookie (`admin_session`)
- **Deploy:** Dockerizzato, con build automatizzate via GitHub Actions

## 📂 Struttura del Progetto (Punti Chiave)
- `src/routes/+page.svelte`: La dashboard pubblica principale in cui gli utenti visualizzano i servizi e i widget. Ha il layout organizzato in card interattive.
- `src/routes/admin/+page.svelte`: Il pannello di amministrazione principale.
- `src/routes/admin/components/AdminSettings.svelte`: Il cuore della pagina Impostazioni. Gestisce sezioni logiche come TEMA (dropdown famiglie), HOME (Navbar fissa, pulsante modifica rapida, counter, stili visuali icone), WIDGET e SICUREZZA.
- `src/routes/api/...`: Endpoint backend (gestione icone, auth, settings, status dei servizi e discovery).
- `src/lib/server/db/`: Contiene la configurazione di Drizzle ORM (`index.ts`) e lo schema del database (`schema.ts`).
- `src/lib/server/discovery.ts`: Core logic per interrogare il demone Docker (tramite socket `/var/run/docker.sock`) e le API di Nginx Proxy Manager.
- `src/lib/components/ui/`: Componenti riutilizzabili dell'interfaccia (come `TextInput`, `SelectInput`, `UrlInput`, `ToggleInput`) costruiti secondo linee guida di Material Design moderne, con form galleggianti, dropdown animati e bordi smussati.
- `data/`: Cartella persistita fuori dal container. Contiene il DB SQLite (`sqlite.db`), le icone caricate dagli utenti (`icons/`) e il file delle impostazioni (`settings.json`).
- `.gemini/`: Cartella **dedicata all'agente Antigravity**. Usala per generare script di prova, salvare backup temporanei di file da modificare, prendere note, o lasciare artefatti testuali (`scratch files`). **Non inquinare mai la root del progetto**.

## ⚙️ Metodologia di Lavoro e Workflow
Quando scrivi codice per TheView, segui *strettamente* queste linee guida:

1. **Test in Locale e Build:** Lo sviluppatore testa tipicamente il codice eseguendo il server dev locale. Usa sempre `npm run check` (o `svelte-check`) e compila il progetto (`npm run build`) per assicurarti che non ci siano errori (specialmente errori di accessibilità `a11y` introdotti da Svelte). 
2. **Svelte 5 Runes:** Utilizza ESCLUSIVAMENTE la sintassi di Svelte 5.
   - Variabili reattive: `let count = $state(0);`
   - Props: `let { myProp } = $props();`
   - Eventi: `onclick={(e: Event) => handler()}` (Usa tipi stretti per gli eventi inline!)
   - Effetti: `$effect(() => { ... })`
3. **Protezione CSRF in Homelab:** Manteniamo sempre `csrf: { checkOrigin: false }` nel file `svelte.config.js`.
4. **UI & UX:** L'interfaccia deve risultare moderna e setosa.
   - Capslock e font audaci per i pulsanti, look Material Design aggiornato.
   - Al posto di classici `<select>`, prediligi UI custom (bottoni visivi affiancati per opzioni limitate) o il componente `SelectInput`.
   - Evita l'`overflow-hidden` nei container principali se taglia sottomenù a comparsa (`absolute`). Risolvi usando angoli arrotondati (`rounded-xl`) direttamente negli elementi interni.
5. **Modifica "In-Place" (ServiceCard):** Le card si convertono nel loro stesso form di modifica espandendosi all'interno della griglia, senza lanciare popup modali.
6. **Accessibilità Svelte (A11y):** Svelte 5 è molto severo con l'accessibilità. 
   - Se crei un handler `onclick` su un elemento non interattivo (come un `div` usato solo per `e.stopPropagation()`), usa `role="presentation"` o `role="none"` per sopprimere l'errore in modo elegante senza ricorrere a commenti `svelte-ignore`.
   - Se devi usare `svelte-ignore`, ricorda che commenti multipli per un singolo elemento (es. `a11y_no_static_element_interactions` e `a11y_click_events_have_key_events`) vanno possibilmente uniti sulla stessa riga separati da uno spazio `<!-- svelte-ignore rule1 rule2 -->`.
7. **Git e Cronologia (WARNING):** MAI, per nessun motivo, lanciare `git reset --hard HEAD` senza essere assolutamente certi che tutto il lavoro sia commitato. In caso di corruzione del file index (es. `fatal: index file smaller than expected`), NON resettare duramente! Ripara l'index semplicemente cancellandolo ed eseguendo `git add .` (es: `rm -f .git/index && git add .`).

## 🧠 Storia Recente e Feature Architetturali
- L'editing veloce *in-place* su `ServiceCard` ora oscura l'handler del drag. Le form labels sono CAPSLOCK per integrarsi col material design.
- La navbar principale (`+layout.svelte`) supporta stati dinamici (solo porta login verde se de-autenticati; porta logout rossa, settings e pulsante matita in home se autenticati). Il layout "matita" può essere attivato o disattivato via `settings.json`.
- Gestione dei Temi Avanzata: Le famiglie di temi (Catppuccin, Dracula) sono raggruppate nella pagina Settings. I temi che non hanno una dualità chiaro/scuro non alterano inaspettatamente la topbar, e il loro stato visivo evidenzia chiaramente il tema attivo (via highlight classes).
- Gli stili delle icone (Rounded, Circular, Square) sono gestibili da 3 grandi pulsanti visivi nell'Admin Panel al posto di una asettica drop-down.
- Sistema di autorisoluzione per `localhost` in Docker (`src/lib/server/dockerHost.ts`) per permettere il ping di servizi interni al network.

Buon vibecoding! Mantieni il codice pulito, testa sempre con build locali per evitare la pagina bianca (Hydration error Svelte 5), lavora in `.gemini/` e prediligi un approccio iterativo e visivamente stupefacente.
