# 🪐 TheView - Antigravity Vibecoding Context

Benvenuto! Se stai leggendo questo file, sei una nuova istanza di Antigravity incaricata di lavorare su **TheView**.
Questo file contiene tutto il contesto, l'architettura e il metodo di lavoro per questo progetto, in modo da poterti allineare immediatamente allo stack e alle preferenze dello sviluppatore.

## 📌 Cos'è TheView?
**TheView** è una dashboard web moderna per homelab e self-hosting, concepita come alternativa leggera, esteticamente appagante e dinamica a progetti come Homer, Heimdall o Dashy.
Il suo scopo è raccogliere i link ai vari servizi (Docker, web apps, ecc.) in un'unica pagina organizzata per categorie, supportando temi scuri/chiari, icone personalizzate, ricerca rapida, controlli drag & drop e **Discovery automatica** (da Docker e Nginx Proxy Manager).

## 🛠️ Tech Stack
- **Framework:** SvelteKit (con Node Adapter)
- **Motore UI:** Svelte 5 (uso estensivo di Runes: `$state`, `$derived`, `$effect`, `onclick`)
- **Stile:** Tailwind CSS v4 (configurato direttamente via Vite e CSS layer) + Material Design vibes
- **Database:** SQLite tramite `better-sqlite3` e `drizzle-orm`
- **Autenticazione:** Sessioni JWT salvate in cookie (`admin_session`)
- **Deploy:** Dockerizzato, con build automatizzate via GitHub Actions

## 📂 Struttura del Progetto (Punti Chiave)
- `src/routes/+page.svelte`: La dashboard pubblica principale in cui gli utenti visualizzano i servizi e i widget. Ha il layout organizzato in card interattive.
- `src/routes/admin/+page.svelte`: Il pannello di amministrazione (protetto da password). Qui risiede la logica per la gestione categorie, servizi, impostazioni NPM e la **Discovery**.
- `src/routes/api/...`: Endpoint backend (gestione icone, auth, settings, status dei servizi e discovery).
- `src/lib/server/db/`: Contiene la configurazione di Drizzle ORM (`index.ts`) e lo schema del database (`schema.ts`).
- `src/lib/server/discovery.ts`: Core logic per interrogare il demone Docker (tramite socket `/var/run/docker.sock`) e le API di Nginx Proxy Manager per trovare e unire servizi non ancora aggiunti in dashboard.
- `src/lib/components/ui/`: Componenti riutilizzabili dell'interfaccia (come `TextInput`, `SelectInput`, `UrlInput`, `ToggleInput`) costruiti secondo linee guida di Material Design moderne, con form galleggianti, dropdown animati e bordi smussati.
- `data/`: Cartella persistita fuori dal container. Contiene il DB SQLite (`sqlite.db`), le icone caricate dagli utenti (`icons/`) e il file delle impostazioni (`settings.json`).
- `.gemini/`: Cartella **dedicata all'agente Antigravity**. Puoi usarla per generare script di prova, salvare backup temporanei di file da modificare, prendere note, o lasciare artefatti testuali (`scratch files`). **Non inquinare mai la root del progetto** con file spazzatura (`patch.py`, `test.js`, ecc.), lavora in questa cartella.

## ⚙️ Metodologia di Lavoro e Workflow
Quando scrivi codice per TheView, segui *strettamente* queste linee guida:

1. **Test in Locale:** Lo sviluppatore testa tipicamente il codice eseguendo il server dev locale (`npm run dev`) con Node.js, puntando a un ambiente di rete locale (es. router). I build completi (tramite GitHub Actions) richiedono minuti, quindi **evita di rompere il server di sviluppo**, usa sempre `svelte-check`, compila il progetto (`npm run build`) per assicurarti che non ci siano errori e controlla sempre i tuoi script.
2. **Deploy via GitHub Actions:** Il progetto utilizza un workflow (`.github/workflows/docker-publish.yml`) che esegue automaticamente la build e il push dell'immagine Docker (multi-arch).
3. **Svelte 5 Runes:** Utilizza ESCLUSIVAMENTE la sintassi di Svelte 5.
   - Variabili reattive: `let count = $state(0);` (NIENTE `let count = 0;` o `$:`)
   - Props: `let { myProp } = $props();`
   - Eventi: `onclick={handler}` (NIENTE `on:click`)
   - Effetti: `$effect(() => { ... })`
4. **Protezione CSRF in Homelab:** Manteniamo sempre `csrf: { checkOrigin: false }` nel file `svelte.config.js`.
5. **UI & UX:** L'interfaccia deve risultare moderna e setosa.
   - Capslock e font audaci per i pulsanti, look Material Design aggiornato.
   - I componenti visivi personalizzati (es. dropdown `SelectInput` fluttuanti) sono SEMPRE da preferire rispetto alle noiose UI native come i classici tag `<select>`.
   - Evita l'`overflow-hidden` nei container principali se questo causa il taglio ("clipping") di sottomenù a comparsa o dropdown `absolute`. Risolvi usando angoli arrotondati (es. `rounded-t-xl`) direttamente negli elementi interni se necessario.
6. **Modifica "In-Place":** Le card (es. `ServiceCard.svelte`) si convertono nel loro stesso form di modifica espandendosi all'interno della griglia, piuttosto che lanciare odiosi e ingombranti popup modali. Disabilita comportamenti in conflitto (come il `drag and drop`) durante le modifiche rapide per evitare anomalie utente.
7. **Gitignore Impeccabile:** Il file `.gitignore` deve essere curato. Non deve mai contenere tracce di file temporanei Python o di Antigravity tranne un match pulito per la directory `.gemini/` e `patch*.py` in caso di dimenticanze. **Pulisci l'ambiente al termine di un lavoro**.

## 🧠 Storia Recente e Bug Risolti
- Implementato l'editing veloce *in-place* su `ServiceCard`, espandendo la card orizzontalmente usando grid span classes, nascondendo gli handler del drag e mettendo in pausa globale `svelte-dnd-action`.
- Disintegrato le noiose `<select>` native. Abbiamo un menù a tendina custom in puro stile Material Design (`SelectInput`), accessibile ma customizzato, impiegato anche nel selettore di protocollo dell'`UrlInput`.
- Il sistema di Discovery avanzato si integra con Nginx Proxy Manager fondendo i dati con Docker ed escludendo via `settings.json` indirizzi IP/MAC blacklistati.
- Sistema di autorisoluzione per `localhost` in Docker (`src/lib/server/dockerHost.ts`). L'API di Node intercetta `localhost`/`127.0.0.1` e lo riscrive dinamicamente nell'IP del docker bridge o network host per comunicare correttamente.

Buon vibecoding! Mantieni il codice pulito, testa sempre con build locali per evitare la pagina bianca (Hydration error Svelte 5), lavora in `.gemini/` e prediligi un approccio iterativo e visivamente stupefacente.
